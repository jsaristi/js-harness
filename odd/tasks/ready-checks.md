# Ready checks

A ready notice is held to the land's own checks, and sessions run the installed harness.
Branch `feat/ready-checks` (unit 1), then a branch of its own for unit 2. Delivery: one PR per unit. Tests: `node --test`.

## Goal
A pull request announced ready is one the land would build, and every session's notices come from the installed `js-harness`.

## Why
360, 365 and 367 were each announced ready and then left out of a land for missing gentle-ai evidence, at about 13 minutes and a relay each. Six of nine running waits used `node bin/js-harness.mjs` from their own worktree, so 349-352 and 357 sent no ready notice: their branch's notify had no `--pr`.

## Done when
- `node --test bin/notify.test.mjs` exits 0
- `node --test bin/lib/protocols-skill.test.mjs` exits 0
- `notify --kind ready --pr <n>` for a merged pull request is refused with "is MERGED, not open", and nothing is recorded

## In scope / Out of scope
- In: `bin/notify.mjs`, `bin/lib/protocols-skill.mjs`, their tests, this document.
- Out: `bin/merge-queue.mjs` and `bin/lib/pull-request.mjs`: their checks are reused as they are, so the land and the notice never disagree.

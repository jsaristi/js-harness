## Findings

- C-a-1. open. bug. `update` and `upgrade` take the next flag as a flag's value and silently drop a missing value: `--repo --home X` makes the repository `--home`, `--source` alone is ignored and the real tags are read, `upgrade --home` with no path falls back to `JS_HARNESS_HOME` or the real home, and `upgrade --prefix --home X` would install with the prefix `--home`. Evidence: `bin/update.mjs:23-26` (`return i !== -1 ? argv[i + 1] : undefined;`), while `bin/lib/args.mjs:7-9` leaves a missing value to "each command's own `requireValue`", which update and upgrade do not have; `JS_HARNESS_HOME=<tmp> node bin/js-harness.mjs update --repo --home <tmp>` → `cannot list the tags of --home: …`, exit 1; `node bin/js-harness.mjs update --source` → `up to date: 0.97.0`, exit 0. Fix: parse update and upgrade with a strict parser that requires values, like `parseStatusArgs` (`bin/update.mjs:202-229`), with a test per flag. Refuter: confirmed.
- C-a-2. open. test-gap. No test gives `update` or `upgrade` a value flag with no value, or a flag where its value should be, so C-a-1 is pinned nowhere. Evidence: `grep -n "requires a value" bin/update.test.mjs` → only `:1261-1264`, all four `statusMain`. Fix: the tests of C-a-1's fix. Refuter: confirmed.
- C-a-3. open. contract. `doctor --hook` given an unknown argument exits 2 and writes to stderr, while SPEC says the session-start hook "always exits 0" and `hookMain`'s doc says "never anything on stderr … always exit 0". Evidence: `bin/doctor.mjs:316-321` (the deliberate exception, explained at `:313-315`); `bin/doctor.mjs:422-426`; `docs/SPEC.md:192`; `JS_HARNESS_HOME=<tmp> node bin/js-harness.mjs doctor --hook --bogus` → `unknown argument: --bogus` + usage, exit 2. Fix: his decision. Either SPEC and the hook's doc name the exception (an older copy on the path), or the hook keeps exit 0. Refuter: confirmed.
- C-a-4. open. test-gap. No test covers the exit-2 path of `doctor --hook <unknown>`. The one argument test is titled "exits 0 … even on unusable arguments" but passes only `--hook --home` (a missing value, which exits 0), so to a reader it pins the opposite of what an unknown argument does. Evidence: `bin/doctor-hook.test.mjs:367-368`; `grep -n "bogus\|unknown arg" bin/doctor*.test.mjs` → no hit. Fix: one test, `--hook --bogus` → 2 with the usage, and the title narrowed to a missing value; this follows from C-a-3's decision. Refuter: confirmed.

## Specs
- S1. The board page declares the `db` capability, keeps its URL, renders the sessions and the timeline from the `events` collection and a `board/summary` document, and refreshes by itself (`onSnapshot`, plus a clock that ages the times). Only an editor writes; viewers read.
- S2. An event row is `{ id, time, session, kind, text, state }` (and `pr` for a ready notice), one per channel notice, id `<time>-<first 8 of the sender id>`. Rows travel in batch documents of the `events` collection (`{ time, rows }`, 100 rows at most, named by the last row): the db holds 25,000 documents at most and its own guide says to aggregate a growing stream. A session's status is the `state` of its latest row: documents are only ever created, because a db write to an existing document needs the version it was read at, which no command can know.
- S3. `js-harness sessions live` reads the project's channel record (the notices `js-harness notify`, the merge queue and the permit hook already write) and turns the notices after its cursor into rows. With `--out <dir>` it writes them as `ArtifactData` batch files of 50 writes at most and prints the call for each; `--sent <file>` moves the cursor to the last row of that file once it was sent; with neither it prints how many rows wait. `--url <board>` is recorded with the cursor and printed back, so the lead's reply names the board. The cursor lives under `<home>/.js-harness/channel/`, which `uninstall` deletes.
- S4. Only a Claude session can write the rows, through `ArtifactData`: no command or hook reaches the artifact's database (it has no API outside the tool). So work sessions write nothing new: each event is the `notify` notice they already send, and the lead sends the batches.
- S5. The rule `live-board`, of Sebastián: work sessions write each event as a notice (a session starts or ends, a step finishes, a pull request opens or merges, a decision is made, spend is reported), the lead sends them to the live board with `sessions live` and its replies point to the board. Declared like `reports-spanish-visual` (PR 595): `bin/lib/rules-data.mjs`, `docs/rule-sources.json`, `docs/RULES.md`, the text in the orchestrator skill, and tests.

## Constraints
- A tag is created and pushed only on his explicit yes, each one — because a tag is a public, installable release that cannot be quietly taken back.
- The tagged commit's `package.json` carries the tag's version, checked when a `v*` tag is pushed — because `upgrade` refuses when the manifest's version differs from the tag (`bin/update.mjs:366-374`).
- The commit that is tagged is the commit the full test ran on — because a test of another commit proves nothing about the release.
- The 0.9.0 code is what runs the upgrade to 1.0.0, so every fix the upgrade path needs is in the commit tagged v0.9.0 — because a bug found after the tag cannot be fixed for that hop.
- The lead's installed copy keeps working at every step, and no throwaway install writes into its pnpm global folder or bin lock — because every session runs its hooks, the relay and the gate from it.

stack-update row named it. Read whole: https://code.claude.com/docs/en/changelog, 2.1.318 (11 added, 11 changed,
15 improved, 47 fixed). Its rows join this table's successor when the app bundles it. What touches the harness:
- Mods (map 10, 14, 15): what a mod attaches at `prompt.submit` stays in the user's turn instead of a system
  message; `$.model.fork` takes an `effort`; the answer to "turn on the mods Claude writes" is recorded. Read
  against that build's mod types (`claude-code.d.ts`: `$.model.fork` with `effort`, `PromptSubmitInput.context`);
  the harness has no mod yet, so nothing changes.

  new sessions (`spawn ENOENT`) after an update removed a running binary, and jobs no longer exit `Not logged in`
  when another terminal signs in again: both help `sessions start` right after an update.
- Background subagents move a shell command to the background after 3 minutes on every provider; a
  `PushNotification` with no status no longer notifies twice (map 16).
